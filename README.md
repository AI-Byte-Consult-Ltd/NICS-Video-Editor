# NICS Video Монтажёр — спецификация сервиса

> Автоматический видеомонтажёр: загружаешь папку с сырыми клипами поездки, на выходе — вертикальный шортс, горизонтальный лонг и 4 обложки (RU/EN × shorts/long), без ручной раскадровки.

Полная версия документа (редактируемая, с комментариями): https://claude.ai/artifact/MjKGQqqwEinLmoFWkDtLBE

---

## 1. Название и позиционирование

**Рабочее название:** NICS Video Монтажёр (бренд уже используется в экосистеме NICS — NICS AI Trader и др., так что это продолжение линейки продуктов).

**Альтернативы:**
- **NICS Reels AI** — короче, понятнее международной аудитории
- **NICS Cutter** — акцент на автоматический «нарезчик»
- **ClipForge by NICS** — более «продуктовое» звучание
- **NICS Автомонтаж** — максимально буквально для рунета

**Ценностное предложение:** загружаете папку с исходным видео (трип, мероприятие, прогулка по городу) — через несколько минут получаете готовый вертикальный Shorts/Reels, горизонтальный travel-ролик и 4 обложки на двух языках, без ручной раскадровки и монтажа. Это не генеративное видео (ИИ ничего не придумывает и не дорисовывает) — это автоматический **монтаж существующих материалов**: система анализирует отснятое, находит лучшие кадры, сама строит хронометраж и склейки.

**Целевая аудитория:** тревел-блогеры, агентства недвижимости/туризма, event-видеографы, обычные пользователи с архивом видео с телефона — все, у кого много сырого материала и нет времени/навыка монтировать.

## 2. Что получает пользователь

На одну загруженную папку с исходниками система выдаёт шесть файлов:

| # | Файл | Параметры |
| --- | --- | --- |
| 1 | `*_shorts_v1.mp4` | Вертикальное 9:16, динамичный стиль монтажа, ~28–33 секунды (сама сокращается, если материала мало) |
| 2 | `*_long_v1.mp4` | Горизонтальное 16:9, плавный travel-стиль, ~60–90 секунд |
| 3 | `*_shorts_v1_title.png` | Обложка для шортс на русском |
| 4 | `*_shorts_v1_title_en.png` | Обложка для шортс на английском |
| 5 | `*_long_v1_title.png` | Обложка для long на русском |
| 6 | `*_long_v1_title_en.png` | Обложка для long на английском |

Оба видео — H.264/AAC, без вшитых субтитров (текст на экране намеренно отключён по умолчанию, чтобы не перегружать кадр), с фоновой музыкой по желанию.

## 3. Технологический стек

Сейчас пайплайн реализован как локальный Python/ffmpeg-инструмент (никаких облачных API вроде Runway/CapCut — всё считается на своём железе). Для сайта это нужно будет обернуть в backend-сервис с очередью задач (см. раздел 8).

| Компонент | Инструмент | Роль |
| --- | --- | --- |
| Детекция сцен | **PySceneDetect** | Режет исходные видео на отдельные планы/кадры по смене кадра |
| Понимание содержимого | **CLIP (ViT-B/32, OpenAI)** | Zero-shot тегирование кадров по фиксированному словарю (пляж, горы, еда, люди и т.д.) — для отбора интересных планов |
| Речь в кадре (опционально) | **faster-whisper (small)** | Транскрипция аудио для будущих субтитров/поиска |
| Текст к клипам (опционально) | **Qwen2.5-1.5B-Instruct (GGUF, llama-cpp-python)** | Локальная LLM для подписей к клипам (сейчас отключено по умолчанию) |
| Сборка плана монтажа | Собственный Python-планировщик (`planner.py`) | Round-robin между источниками, сильное открытие/закрытие, таргетная длительность по стилю |
| Сборка видео | **FFmpeg** (xfade/concat цепочка, drawtext, vidstab-стабилизация) | Финальный рендер видео из отобранных клипов |
| Аппаратное ускорение | **h264_qsv** (Intel Quick Sync) с fallback на libx264 | Ускоренное кодирование выходного видео |
| Обложки | FFmpeg drawtext/drawbox поверх кадра из видео | См. раздел 6 |

**Важно:** всё работает полностью офлайн — ни один видеофайл и кадр не отправляются во внешние облачные API — это важный аргумент для приватности (личные/семейные видео). На сайте это придётся либо сохранить (собственный GPU-сервер с Quick Sync/NVENC), либо явно заявить облачную обработку как компромисс скорости.

## 4. Пайплайн шаг за шагом

1. **Загрузка.** Пользователь загружает папку/несколько файлов mp4 (сейчас — любое количество, от 3 до 40+ клипов на локацию). Исходники никогда не модифицируются, всё копируется в рабочую папку.
2. **Анализ (`analyze.py`).** Для каждого файла: детекция сцен (PySceneDetect) + эвристическая оценка качества/движения кадра + CLIP-теги по содержимому. Результат кэшируется по хэшу размера+даты файла, повторный запуск на тех же файлах не пересчитывает. **Это самый долгий этап** — на один час сырого материала может уйти от 15–20 минут до нескольких часов на одном CPU-ядре без GPU-ускорения этого шага.
3. **Сборка плана (`planner.py`).** Из проанализированных клипов строится таймлайн: выбираются лучшие по оценке отрезки, чередуются источники (round-robin, чтобы один видеофайл не занимал весь ролик), строится сильное открытие/закрытие, добирается общая длительность под целевой тайминг стиля. Если исходников мало — длительность честно уменьшается с предупреждением в логах, без дублирования кадров. Результат — `plan.json` с точными таймкодами каждого куска в исходном файле.
4. **Рендер (`render.py`).** FFmpeg строит filter-граф из `plan.json`: нарезка кусков, xfade/cut-переходы между ними, опциональная vidstab-стабилизация трясущихся кадров, сводка с музыкой (если запрошена), кодирование в h264_qsv (аппаратное ускорение Intel Quick Sync, с автоматическим fallback на программный libx264, если аппаратного энкодера нет). Для музыки поддерживается старт с любой точки трека (чтобы петля длинного видео начиналась с самой энергичной части песни, как делают TikTok/Instagram-редакторы).
5. **Выбор фона для обложек.** Строится «контактный лист» — сетка кадров-кандидатов из разных точек таймлайна, среди них вручную/автоматически выбирается самый узнаваемый/яркий кадр (избегая размытых, тёмных или слишком «людных» крупных планов).
6. **Генерация 4 обложек (`make_cover.py`).** FFmpeg берёт кадр из выбранного клипа и накладывает слой текста в фирменном стиле (см. раздел 6) — отдельно для вертикального и горизонтального кадра, на двух языках.
7. **Проверка.** Автоматическая валидация через ffprobe (наличие video/audio потоков, корректная длительность, целый moov atom) перед выдачей файлов пользователю.

**Итоговое время:** от 2–4 минут для небольших папок (5–10 коротких клипов) до нескольких часов для больших папок с длинными исходниками (3–5+ минут одним файлом) на текущем CPU-only оборудовании — ключевой момент для планирования инфраструктуры (см. раздел 8).

## 5. Логика шортс vs лонг

Оба видео строятся из **одного** анализа исходников, но двумя разными проходами планировщика — анализ не дублируется.

| Параметр | Shorts | Long |
| --- | --- | --- |
| Формат кадра | 9:16 (вертикальный) | 16:9 (горизонтальный) |
| Стиль монтажа | `dynamic` — короткие куски, быстрые переходы, акцент на энергии | `travel` — более длинные планы, плавное повествование |
| Целевая длительность | 28–32 сек | 70–90 сек (сокращается для малых папок) |
| Кадрировка исходников | Центрированный кроп из 16:9-исходников в 9:16 | Исходный кадр сохраняется почти полностью |
| Назначение | TikTok, Instagram Reels, YouTube Shorts | YouTube, сайт, портфолио |

**Важный нюанс:** если в папке мало исходников, система честно сокращает длительность вместо того, чтобы дублировать кадры для добора до целевого хронометража — это надо чётко отразить в UI сайта (предупредить пользователя, если фактическая длительность сильно ниже целевой).

## 6. Дизайн обложек

Стиль — «постерный», в духе карточек Disney+/стриминговых сервисов: фон — реальный кадр из видео, поверх — крупный объёмный заголовок внизу слева.

**Структура слоёв (снизу вверх):**
1. Фоновый кадр из видео (см. раздел 4, пункт 5)
2. Полупрозрачная затемняющая подложка в нижней трети кадра — для читаемости текста независимо от того, что на фоне
3. Кикер «Nics Studio» — маленький рукописный/скриптовый шрифт, белый, над заголовком
4. Заголовок локации/темы — крупный жирный шрифт (скруглённый, игривый — типа Comic Sans Bold), набран отдельной трёхслойной обводкой для «наклеенного» объёма (как в логотипах мультфильмов):
   - **Заливка:** жёлтый `#FFD23C`
   - **Внешний контур (толстый, 13–14px):** красный `#B8231A`
   - **Внутреннее кольцо (7px):** белый
   - **Тонкая обводка (2px) вокруг самой заливки:** чёрный @35% непрозрачности
   - Заголовок 1–2 строки максимум (длинные названия сокращаются или разбиваются на слова пробелами, никогда дефисом — дефисы ломают автоперенос)
5. Подзаголовок (страна/регион) — белый жирный текст под заголовком, без двухслойной обводки

**Два языка, четыре файла:** для каждого из 2 форматов (shorts/long) генерируется русская и английская версия — один и тот же фоновый кадр, переведённый заголовок.

**Выбор фонового кадра — важный технический нюанс:** для shorts-обложки кадр берётся с центрированным кропом в 9:16 — если исходный кадр широкий (например, городская улица), важная деталь может обрезаться по краям — нужен ручной/автоматический превью перед выводом, чтобы перевыбрать кадр, если главный объект обрезан.

**Пример строки названия файла:** `sanfrancisco_shorts_v1_title_en.png`.

## 7. Предлагаемый UX на сайте

**Шаг 1 — загрузка.** Drag-and-drop или выбор папки/нескольких файлов mp4/mov. Показать суммарный размер и длительность исходников сразу после загрузки — это напрямую влияет на ожидаемое время обработки (см. раздел 8).

**Шаг 2 — настройки.** Минимальный набор настроек, чтобы не перегружать UI:
- Название/тема ролика (для заголовка на обложках) — текстовое поле, RU и EN
- Подзаголовок (страна/регион) — текстовое поле, RU и EN
- Стиль: «Динамичный» / «Путешествие» (dynamic/travel) — влияет на темп монтажа обоих видео
- Фоновая музыка: без музыки / выбрать из библиотеки треков / загрузить свой файл (с автоматическим поиском «хука» через анализ энергии трека)
- Целевая длительность shorts и long (слайдеры с разумными дефолтами)

**Шаг 3 — обработка.** Экран прогресса с чёткими этапами (анализ → сборка плана → рендер → обложки) и честным ETA — процесс может занять от пары минут до нескольких часов, поэтому обязателен асинхронный режим: уведомление на email/push по завершению, а не «ждите открытую вкладку».

**Шаг 4 — результат.** Превью всех 6 файлов (2 видео + 4 обложки), кнопки скачать поотдельно/архивом zip. Желательно — возможность перегенерировать только обложки с другим фоновым кадром/текстом без повторного рендера видео (дёшево и быстро, так как фоновый кадр уже извлечён из готового плана).

## 8. Технические требования и ограничения

Это самый важный раздел для агента, который будет собирать сервис — нынешний пайплайн не готов к прямому промышленному использованию без доработки.

**Вычислительная нагрузка.** Сейчас всё работает на одной рабочей станции без очереди задач. Для многопользовательского сервиса нужна очередь задач (например Celery/RQ + Redis или аналог) и пул обработчиков, чтобы один тяжёлый заказ не блокировал остальных.

**Гибкая продолжительность.** Время обработки прямо зависит от объёма и длительности исходников — на практике один пятиминутный файл может занять часы анализа на CPU-ядре без GPU. Для предсказуемого SLA нужно либо ускорить анализ (batch/GPU-версия детекции сцен), либо честно показывать пользователю реалистичное время ожидания.

**Гибридное аппаратное ускорение.** `h264_qsv` требует Intel-процессор с Quick Sync на сервере рендера — это сужает выбор облачного провайдера (большинство облачных GPU-инстансов — NVIDIA, без Quick Sync). Альтернатива: перейти на NVENC или libx264 (медленнее, но универсально).

**Хранилище.** Исходные видео могут весить сотни МБ каждое — нужно object storage (S3-совместимый), а не загрузка на веб-сервер, и TTL на хранение исходников/результатов после скачивания.

**Локальные модели.** CLIP, faster-whisper и Qwen2.5 хранятся на диске (несколько ГБ веса) — на сервере нужно заранее скачать и закэшировать их, иначе первый запуск сервиса зависнет.

**Что уже проверено и работает стабильно:**
- Весь пайплайн проверен полностью офлайн, включая отключённый интернет — никаких скрытых вызовов к облачным AI-сервисам
- Обработаны десятки локаций с разным объёмом исходников (от 3 до 40+ файлов)
- Устойчив к кириллическим путям/именам файлов (UTF-8 везде в subprocess)

**Известные границы текущей реализации:**
- Автоматический выбор фонового кадра для обложки иногда попадает на неудачный/размытый кадр — нужен экран превью с возможностью выбрать другой кадр вручную (на сайте это критичнее важнее, чем в текущем ручном процессе)
- Ken Burns (плавный зум на статичных кадрах) отключён из-за ограничения текущей сборки ffmpeg (рабочее решение через `zoompan` с достаточным запасом масштабирования найдено и пригодно для отдельных сцен, но не встроено в основной пайплайн как стандарт)
- Зависимость от локальной папки с шрифтами для текста обложки — нужно зашить в образ сервиса, а не ссылаться на шрифты, установленные в ОС
- Нет автоматической очереди/масштабирования — нужно спроектировать с нуля для production

## 9. Монетизация и тарифы (открытый вопрос)

Этот раздел не зафиксирован — решение остаётся за владельцем сервиса. Возможные модели, исходя из вычислительной стоимости одной генерации:

| Модель | Описание |
| --- | --- |
| Посленно оплата за ролик | Фиксированная цена за одну загрузку/один комплект из 6 файлов — проще всего для разового клиента |
| Подписка с лимитом | N роликов/месяц за фиксированную плату — подходит для блогеров с регулярным контентом |
| Кредиты | Покупка пакета генераций вперёд, списывается за каждый рендер |
| Freemium | Первый ролик бесплатно (с водяным знаком), дальше платно без водяного знака |

**На что обратить внимание при выборе:** стоимость генерации сильно зависит от объёма исходников (раздел 8) — тариф стоит привязать либо к суммарному весу/длительности загружаемого, либо ввести потолок (например, «до 30 минут исходника на ролик» на базовом тарифе).

## 10. Запуск для сайта (воркер)

Сайт кладёт задачу и исходники в хранилище, а воркер забирает их по HTTPS, монтирует и отдаёт 6 файлов обратно. Входящих подключений воркеру не нужно, поэтому он работает и на рабочей станции, и на сервере.

- `scripts/pipeline.py` — одна полная задача (лонг 16:9, шортс 9:16, 4 обложки RU/EN), то же, что `make_video.bat`, но вызывается из Python.
- `scripts/worker.py` — цикл: `claim` → скачать исходники частями по 3 МБ → `pipeline.run_job` → загрузить результаты частями → `complete`/`fail`. API — webhooks n8n (`nics-video-worker*`), контракт описан в начале файла.
- Пути и шрифты настраиваются переменными окружения: `NICS_VIDEO_ROOT` (по умолчанию `D:\NICS-VIDEO` на Windows и `~/nics-video` на Linux), `NICS_VIDEO_CAPTION_FONT`, `NICS_VIDEO_TITLE_FONT`, `NICS_VIDEO_KICKER_FONT`. На Linux вместо шрифтов Windows используется DejaVu.

**На рабочей станции (Windows):** создать `scripts\worker.env` со строкой `NICS_VIDEO_WORKER_TOKEN=...` (тот же токен сохраняется в n8n через форму `nics-video-set-worker-token`), запустить `scripts\start_worker.bat`. Адрес API по умолчанию `https://n8n.aibyteconsult.com/webhook`, другой задаётся через `NICS_VIDEO_API_BASE`.

**На сервере (Linux):**

```
docker build -t nics-video-worker .
docker run -d --restart unless-stopped --name nics-video-worker \
  -e NICS_VIDEO_WORKER_TOKEN=... \
  -v nics-video-data:/data nics-video-worker
```
